# Documentation ownership

STATADIC's package documentation is the canonical source; Sphinx reads it directly
with this application's configuration. Teaching notebooks live beside the pages
under the package docs tree. The app owns rendering and validation, while static
snapshots and source downloads are generated in ignored build output.
The app is an internal workspace consumer and does not add documentation
dependencies to STATADIC's distribution. A successful site build does not qualify
scientific results or prove mathematical claims.

The build selects publication exports explicitly, never by scanning ambient
campaign directories. Release selections follow orchestrator verification of
the wheel and scope. Rendering distinguishes historical reports and selected
release reports; neither label itself grants qualification. Figures read the
retained summary's uncertainty bounds, failures and frozen decision thresholds,
without rerunning trials or replacing scientific dispositions.

The formal section consumes a current compiled Lean certification artifact.
Canonical Markdown stubs project registry content at Sphinx source-read time;
tracked documentation never acquires generated proof badges. Bibliographic
metadata comes from the same governed references and BibTeX export as LaTeX.
The build certifies proofs and renders the blueprint before Sphinx; unresolved
all-method obligations are visible and remain distinct from integrity failures.

The website uses Shibuya's article layout with licensed local serif fonts and a
small black/Delft-blue stylesheet. The supplied curve-fit SVG is the header logo
and favicon; the rest of the presentation remains free of decorative artwork.
Documentation separates learning, tasks, concepts, reference and evidence.
The root README retains its word budget. Page-type schemas set section budgets
for the user documentation. Each self-contained marimo notebook owns its prose,
numerical recipe, figures, controls and output tests. Native Sphinx pages render
executed outputs and offer source downloads and optional server-mode molab links.
The site itself requires neither browser-WASM nor a hosted kernel.

`statadic_docs_pages` owns notebook execution, content-based caches and conversion
to native document nodes. `statadic_docs_labs` retains formal, release and
scientific evidence tooling. These packages remain internal workspace consumers.

The scientific qualification runner owns retained evidence and an isolated installed-wheel
test environment. It exports reference dependencies from the workspace lock,
never installs editable STATADIC into that environment, and records source/artifact
hashes and per-study dispositions. Its verification rejects changed evidence or
source trees. Human source-fidelity review remains separate from compilation.

Package publication belongs to `infra/release` and the reusable package-validation
workflow. Its standard-library promotion driver verifies complete package evidence
and publishes the exact tested distributions without importing this application.
Documentation builds and scientific qualification remain separate from that gate.

An explicit release scope retains every required variant's canonical campaign
cells and selects additional statistical tests by exact parameterized node.
Missing, duplicate, skipped or extra supplemental cells fail verification, as do
changed test, mapping, wheel or scope identities. A campaign-only variant has an
explicit route rather than inheriting unrelated statistical tests. The default
release retains all-method qualification. Bounded numerical controls cannot
satisfy a separate large spatial-survival accuracy or refit contract.
