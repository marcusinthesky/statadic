# Value export specification

Scope: two new `Report` methods and private helpers in
`src/python/packages/statadic/src/statadic/api/reporting.py`. No dataclass field changes.

## Signatures

```python
def to_values(
    self, *, prefix: str, digits: int = 6, decimals: int | None = None
) -> str: ...

def save_values(
    self, path: str | Path, *, prefix: str, digits: int = 6,
    decimals: int | None = None,
) -> None: ...
```

`prefix` must match `^[a-z][a-z0-9-]*$`; `digits` and `decimals` follow
`to_latex`. Invalid values raise `ValueError`. `save_values` writes `to_values(...)`
as UTF-8 with `\n` newlines and creates no directory.

## File

```latex
% Generated by statadic Report.save_values from: Poisson inference
\providecommand{\jcDeclareValue}[2]{\expandafter\gdef\csname jc@value@#1\endcsname{#2}}
\providecommand{\jcvalue}[1]{\ifcsname jc@value@#1\endcsname\csname jc@value@#1\endcsname\else\PackageError{statadic}{Undefined value '#1'}{Export it with Report.save_values.}\fi}
\providecommand{\jcnum}[1]{\num{\jcvalue{#1}}}
\jcDeclareValue{poisson-intercept-estimate}{-0.4942}
\jcDeclareValue{poisson-load-estimate}{0.2998}
\jcDeclareValue{poisson-n-observations}{400}
% unavailable: poisson-rho-estimate (singular)
```

- The first line is the comment `% Generated by statadic Report.save_values from: <title>`
  with the title on one line.
- The three `\providecommand` lines are written verbatim. They store values under
  the same control-sequence names as `src/latex/templates/statadic-manuscript.sty`, so
  a manuscript that loads that style keeps its own definitions and reads the values. The coordinator compiled this file alone and after
  the style, offline.
- Declarations follow report order: parameters, then metrics, then tests.

## Keys

`slug(text)` lowercases the text, replaces each run of characters outside
`[a-z0-9]` with one `-`, and strips leading and trailing `-`. An empty slug raises
`ValueError`. Keys use the retained names, never display labels.

| Source | Key |
| --- | --- |
| Parameter row | `{prefix}-{slug(name)}-{q}`, `q` in `estimate`, `se`, `statistic`, `p`, `lower`, `upper` |
| Metric | `{prefix}-{slug(name)}` |
| Test row | `{prefix}-{slug(name)}-{q}`, `q` in `statistic`, `p`; also `df` for chi-square, `df1` and `df2` for F |

Duplicate keys raise `ValueError` naming both sources, for example
`x_1` and `x-1`, or a metric `x-estimate` beside a parameter `x`.

## Value text

| Value | Text |
| --- | --- |
| `int` | Exact digits |
| `float`, `decimals` given | `f"{value:.{decimals}f}"` |
| `float`, otherwise | The table's significant-digit rule, with a negative exponent written as `1.20e-9` |
| Parameter or test p-value | `< 0.001` below 0.001, otherwise `=` and three decimals, for example `= 0.497` |
| Degrees of freedom | Integral values as integers, otherwise `f"{value:.2f}"` |

A number is siunitx input, so `\jcnum{key}` prints a true minus, digit grouping
and `1.20 \times 10^{-9}`. A p-value includes its relation so that `$p \jcvalue{key}$`
reads p = 0.497 or p < 0.001 with relation spacing.

## Unavailable values

A quantity that is `None` because it is unavailable is not declared. For each
unavailable row or metric, write one `% unavailable: <key> (<reason>)` line per key
it would have declared. A quantity that was never requested, such as a p-value
without a null, is omitted silently. A manuscript that uses an undeclared key
fails to compile with the key in the message. `report.require_available(...)`
remains the way to require values before export.
